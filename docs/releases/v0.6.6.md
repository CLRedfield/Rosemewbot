# Rosemewbot v0.6.6

发布日期：2026-10-28。本次说明涵盖自上一公开版本 v0.6.4 以来的全部主应用更新，包括本地 v0.6.5 的 SnowLuma 迁移。

## 主要更新

- **QQ 接入改为 SnowLuma。** 使用官方 Windows QQ 完成登录，由 SnowLuma 接入所选账号，消息继续交给 AstrBot。运行控制、首次接入向导、内嵌后台、诊断与日志入口同步更新。
- **只连接指定 QQ。** 支持从已识别账号中选择，也可在 QQ 尚未启动时手动保存 QQ 号。在线状态同时检查所选账号的登录、接入和 OneBot 连接，避免把另一只在线的个人 QQ 当成机器人。
- **启动步骤分别可选。** 在“设置 → 启动与连接”中分别控制 Windows 登录时打开控制台、登录时启动机器人、手动打开应用时启动机器人、SnowLuma 自动登录、QQ 自动启动与指定账号自动连接。“打开应用时启动机器人”默认关闭，其余原有偏好沿用。
- **内嵌 SnowLuma 自动认证。** 自动同步本机会话，支持令牌过期、清除与轮换后重新认证；关闭自动登录时清除由 Rosemewbot 写入的会话。密码和令牌不放入页面 URL。
- **恢复过程保留 QQ 登录。** 停止或重启组件时卸载所选账号的接入，保留官方 QQ 进程。自动恢复只处理故障组件；QQ 会话失效时等待用户在官方客户端重新登录。

## 修复与可靠性

- 修复上次关机遗留的恢复状态可能绕过启动开关、在冷启动时意外启动机器人的问题。
- QQ 列表检查和后台身份刷新覆盖“QQ 登录完成但身份缓存尚未更新”的情况；确认账号匹配后才接入。
- QQ 自动启动会复用目标账号窗口或待登录窗口，管理接口尚未就绪时推迟检查，避免重复弹窗。
- 关闭自动连接后停用受管 OneBot 连接并停止自动接入，恢复逻辑遵守该设置；保留用户自定义连接。
- 自动认证失败增加退避，故障恢复和接入尝试设有次数及间隔限制，避免持续重启或反复请求。
- SnowLuma 自带更新器创建的子进程使用隐藏控制台启动，同时保留上游更新与退出行为。
- SnowLuma 更新与修复保留 config、data、logs，使用独立的可用版本快照，避免混用旧 NapCat 快照。

## 从 v0.6.4 升级

1. 退出旧版 Rosemewbot，在**原安装位置**安装 v0.6.6，继续使用原目录旁的 `Rosemewbot-data` 数据目录。
2. 打开应用，在“运行控制”按提示准备或更新组件，下载 SnowLuma。应用下载、首次准备、组件更新和修复需要能够连接 GitHub；下载期间请保持网络可用。
3. 在官方 Windows QQ 中登录机器人账号，再到“设置 → 启动与连接”选择或填写该 QQ 号。
4. 点击“启动机器人”，确认所选 QQ 在线且 OneBot 已连接。按需要开启自动启动选项。

原有 AstrBot 模型配置、人设、插件和历史数据库继续使用。QQ 登录由官方客户端管理，不迁移 NapCat 登录凭据；首次登录或会话失效时仍需在 QQ 中完成扫码或设备验证。
